# 02. 도메인 규칙

## 1. 엔티티 관계

```
Doctor (의료진)  1 ── N  Visit (방문)
Visit            1 ── N  Question (질문)
Visit            1 ── N  Commitment (약속)
```

- Question·Commitment는 조회 편의를 위해 `doctor`도 함께 가진다. **항상 `visit.doctor`와 같은 의료진**이어야 하며, 생성 시 `visit.getDoctor()`로 채운다(외부에서 따로 받지 않음).
- 모든 연관관계는 `@ManyToOne(fetch = FetchType.LAZY, optional = false)` 단방향. 컬렉션(`@OneToMany`)을 두지 않는다.
- 엔티티에 public setter 금지. 상태 변경은 의미 있는 메서드로만 한다.
- 생성은 정적 팩토리 `create(...)`. 기본 생성자는 `protected`.
- `createdAt`, `updatedAt`은 `BaseTimeEntity`(`@MappedSuperclass`, `@PrePersist`/`@PreUpdate`)로 관리.

## 2. Doctor (의료진)

| 필드 | 타입 | 필수 | 제약 |
| --- | --- | --- | --- |
| id | Long | - | PK |
| name | String | O | 1~30자 |
| hospital | String | O | 1~50자 |
| department | String | O | 1~30자 |
| memo | String | X | 최대 500자 |
| nextVisitDate | LocalDate | X | 과거 날짜 허용 (지난 예정일 표시용) |
| deletedAt | LocalDateTime | X | null이면 활성, 값이 있으면 숨김(D14) |

메서드

- `static Doctor create(name, hospital, department, memo, nextVisitDate)`
- `void update(name, hospital, department, memo, nextVisitDate)` — nextVisitDate가 null이면 **null로 지운다**(의료진 수정 화면은 값 그대로 보냄)
- `void changeNextVisitDate(LocalDate date)` — **null이면 아무것도 바꾸지 않는다**(D13, 방문 기록 화면용)
- `void delete(LocalDateTime now)` — deletedAt = now. 이미 삭제됐으면 아무것도 안 함
- `boolean isDeleted()`

## 3. Visit (방문)

| 필드 | 타입 | 필수 | 제약 |
| --- | --- | --- | --- |
| id | Long | - | PK |
| doctor | Doctor | O | |
| visitDate | LocalDate | O | 오늘 이후 불가 (오늘은 가능) |
| memo | String | X | 최대 1000자 |

메서드

- `static Visit create(Doctor doctor, LocalDate visitDate, String memo)`
- `void update(LocalDate visitDate, String memo)` — D15. 날짜·메모만

삭제 규칙(D16) — `VisitService.delete`에서:

1. 그 방문의 질문 중 `DELIVERED`가 하나라도 있으면 `InvalidStateException("VISIT_HAS_DELIVERED", "전달 완료된 질문이 있는 방문 기록은 삭제할 수 없습니다.")`
2. 아니면 그 방문의 질문 → 약속 → 방문 순서로 삭제 (벌크 삭제 JPQL `delete from Question q where q.visit.id = :visitId` 사용 가능)

## 4. Question (질문)

| 필드 | 타입 | 필수 | 제약 |
| --- | --- | --- | --- |
| id | Long | - | PK |
| doctor | Doctor | O | = visit.doctor |
| visit | Visit | O | |
| content | String | O | 1~500자 |
| productTag | ProductTag | X | P1. T15 전까지 항상 null |
| status | QuestionStatus | O | 생성 시 `UNANSWERED` |
| answer | String | 조건부 | READY, DELIVERED에서 필수. 1~1000자 |
| sourceType | SourceType | 조건부 | READY, DELIVERED에서 필수 |
| sourceDetail | String | X | 최대 200자 |
| answeredAt | LocalDateTime | X | 마지막으로 답변을 저장한 시각 |
| deliveredAt | LocalDateTime | X | 전달 완료 시각 |

"받은 날"은 저장하지 않고 `visit.visitDate`를 쓴다(결정 R1).

### 4.1 enum

```java
public enum QuestionStatus {
    UNANSWERED("미답변"), CHECKING("확인 중"), READY("답변 준비됨"), DELIVERED("전달 완료");
}
public enum SourceType {
    LABEL("허가사항"), CLINICAL("임상자료"), MEDICAL_TEAM("학술팀 회신");
}
public enum ProductTag {   // P1
    ROSUZET("로수젯"), AMOSARTAN("아모잘탄"), AMOPREL("아모프렐"), EFE("에페"), ROLONTIS("롤론티스");
}
```

각 enum은 `String label` 필드와 getter를 가진다. DB에는 `@Enumerated(EnumType.STRING)`으로 영문 이름 저장. API 응답에는 영문 이름만 보낸다(라벨은 프론트가 가진다, `07_프론트_구현가이드.md` 4절).

### 4.2 상태 전이

```
UNANSWERED ──startChecking()──▶ CHECKING
UNANSWERED ──answer(...)──────▶ READY
CHECKING   ──answer(...)──────▶ READY
READY      ──answer(...)──────▶ READY        (답변 수정)
READY      ──deliver()────────▶ DELIVERED    (이후 완전 잠금, D11)
```

| 메서드 | 허용 상태 | 동작 | 그 외 → 예외 코드 / 메시지 |
| --- | --- | --- | --- |
| `startChecking()` | UNANSWERED | status = CHECKING | `QUESTION_NOT_UNANSWERED` / `미답변 상태의 질문만 확인을 시작할 수 있습니다.` |
| `answer(answer, sourceType, sourceDetail, now)` | UNANSWERED, CHECKING, READY | 답변·출처 저장, answeredAt = now, status = READY | `QUESTION_LOCKED` / `전달 완료된 질문은 수정할 수 없습니다.` |
| `deliver(now)` | READY | deliveredAt = now, status = DELIVERED | `QUESTION_NOT_READY` / `답변 준비됨 상태의 질문만 전달 완료로 바꿀 수 있습니다.` |
| `changeContent(content)` | UNANSWERED, CHECKING, READY | content 변경 (상태 유지) | `QUESTION_LOCKED` / `전달 완료된 질문은 수정할 수 없습니다.` |
| 삭제 (서비스) | UNANSWERED, CHECKING, READY | 삭제 | `QUESTION_LOCKED` / `전달 완료된 질문은 삭제할 수 없습니다.` |

- `answer()`에서 answer가 공백이거나 sourceType이 null이면 `IllegalArgumentException` (요청 검증에서 먼저 막히므로 방어 코드).
- 정적 팩토리: `static Question create(Visit visit, String content)` — doctor = visit.getDoctor()

## 5. Commitment (약속)

| 필드 | 타입 | 필수 | 제약 |
| --- | --- | --- | --- |
| id | Long | - | PK |
| doctor | Doctor | O | = visit.doctor |
| visit | Visit | O | |
| content | String | O | 1~300자 |
| dueDate | LocalDate | O | 생성 시·기한 변경 시 오늘 이전 불가 (R5) |
| done | boolean | O | 기본 false |
| doneAt | LocalDateTime | X | |

메서드

- `static Commitment create(Visit visit, String content, LocalDate dueDate)`
- `void update(String content, LocalDate dueDate)` — done이면 `InvalidStateException("COMMITMENT_DONE", "완료한 약속은 완료를 취소한 뒤 수정할 수 있습니다.")`
- `void complete(LocalDateTime now)` — 이미 완료면 아무것도 안 함
- `void reopen()` — done = false, doneAt = null. 이미 미완료면 아무것도 안 함
- `boolean isOverdue(LocalDate today)` = `!done && dueDate < today`
- `boolean isDueToday(LocalDate today)` = `!done && dueDate == today`

R5 검사(서비스에서): 요청의 dueDate가 **기존 값과 다르고** today보다 이전이면 검증 에러(필드 `dueDate`, `약속 기한은 오늘 이전일 수 없습니다.`).

## 6. 예외 체계

| 예외 | HTTP | 용도 |
| --- | --- | --- |
| `NotFoundException(String message)` | 404 | 대상 없음 또는 숨김 의료진 관련 (R7). 메시지 `요청한 정보를 찾을 수 없습니다.` |
| `InvalidStateException(String code, String message)` | 409 | 상태 규칙 위반 (위 표의 코드) |
| `FieldValidationException(List<FieldErrorItem> errors)` | 400 | 서비스에서 하는 필드 검증 (R5, 방문 날짜 미래, 약속 기한 과거). 여러 필드 에러를 한 번에 담는다. 단일 에러용 생성자 `(String field, String message)`도 둔다 |
| Bean Validation 실패 | 400 | 요청 DTO 검증 |

응답 형식은 `05_API_명세.md` 1절.

## 7. 조회 규칙

공통: **숨김 의료진(deletedAt not null)과 그에 딸린 데이터는 모든 조회에서 제외**(R7). 모든 JPQL에 `d.deletedAt is null` 조건을 넣는다.
`today = LocalDate.now(clock)`

### 7.1 홈

| 영역 | 조건 | 정렬 |
| --- | --- | --- |
| 기한 지난 약속 | done = false AND dueDate < today | dueDate ASC, id ASC |
| 오늘까지인 약속 | done = false AND dueDate = today | id ASC |
| 이번 주 방문 예정 | nextVisitDate IS NOT NULL AND nextVisitDate <= today + 6 | nextVisitDate ASC, name ASC |
| 질문 현황 | 상태별 개수 (UNANSWERED, CHECKING, READY) | - |

- 이번 주 방문 예정 각 의료진: READY 질문 수, 미완료 약속 수, `pastDue`(nextVisitDate < today)
- 의료진별 숫자는 `GROUP BY doctor.id` 집계 쿼리 2개로 가져와 합친다(N+1 금지).

### 7.2 의료진 상세

| 영역 | 조건 | 정렬 |
| --- | --- | --- |
| 전달할 답변 | status = READY | answeredAt ASC |
| 확인이 필요한 질문 | status IN (UNANSWERED, CHECKING) | visit.visitDate ASC, id ASC |
| 남은 약속 | done = false | dueDate ASC, id ASC |
| 최근 방문 | 가장 최근 Visit 1건 | visitDate DESC, id DESC |
| 방문 기록 | 전체 Visit | visitDate DESC, id DESC |
| 전달 완료한 질문 | status = DELIVERED | deliveredAt DESC |
| 완료한 약속 | done = true | doneAt DESC |

### 7.3 질문함

- 상태 필터(필수, 기본 UNANSWERED). P1에서 제품 필터 추가.
- 정렬: visit.visitDate ASC, id ASC. 단 DELIVERED는 deliveredAt DESC.
- 상태별 개수 4개를 함께 반환.

### 7.4 의료진 검색

- `q`가 있으면 name 또는 hospital에 q가 포함(대소문자 무시). department는 대상 아님.
- 정렬: name ASC, id ASC.

## 8. 입력 검증 메시지

요청 DTO에 Bean Validation을 붙이고, 아래 메시지를 **그대로** 쓴다. 문자열은 저장 전 `strip()`, 선택 필드의 빈 문자열은 `null`로 저장.

| --- | --- | --- | --- |
| DoctorRequest | name | NotBlank / Size(max=30) | `이름을 입력해 주세요.` / `이름은 30자 이하로 입력해 주세요.` |
| | hospital | NotBlank / Size(max=50) | `병원을 입력해 주세요.` / `병원은 50자 이하로 입력해 주세요.` |
| | department | NotBlank / Size(max=30) | `진료과를 입력해 주세요.` / `진료과는 30자 이하로 입력해 주세요.` |
| | memo | Size(max=500) | `메모는 500자 이하로 입력해 주세요.` |
| VisitCreateRequest | visitDate | NotNull + 서비스에서 미래 검사 | `방문 날짜를 입력해 주세요.` / `방문 날짜는 오늘 이후일 수 없습니다.` |
| | memo | Size(max=1000) | `메모는 1000자 이하로 입력해 주세요.` |
| | questions | Size(max=10) | `질문은 한 번에 10개까지 입력할 수 있습니다.` |
| | questions[i].content | NotBlank / Size(max=500) | `질문 내용을 입력해 주세요.` / `질문은 500자 이하로 입력해 주세요.` |
| | commitments | Size(max=10) | `약속은 한 번에 10개까지 입력할 수 있습니다.` |
| | commitments[i].content | NotBlank / Size(max=300) | `약속 내용을 입력해 주세요.` / `약속은 300자 이하로 입력해 주세요.` |

| | sourceType | NotNull | `출처를 선택해 주세요.` |
| | sourceDetail | Size(max=200) | `출처 상세는 200자 이하로 입력해 주세요.` |
| CommitmentUpdateRequest | content | NotBlank / Size(max=300) | `약속 내용을 입력해 주세요.` / `약속은 300자 이하로 입력해 주세요.` |
| | dueDate | NotNull + R5 | `약속 기한을 입력해 주세요.` / `약속 기한은 오늘 이전일 수 없습니다.` |

- 리스트 항목 에러의 field 이름: `questions[0].content`, `commitments[2].dueDate` 형식 (Spring 기본 경로 그대로).
- 빈 입력 행은 **프론트가 전송 전에 제거**한다(내용·기한이 모두 빈 행). 백엔드는 받은 항목을 전부 검증한다.
- 날짜 형식 오류(파싱 실패)는 field 에러 `날짜 형식이 올바르지 않습니다.`
