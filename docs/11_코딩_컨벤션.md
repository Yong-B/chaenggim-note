# 11. 코딩 컨벤션 (백엔드)

> 사용자가 정한 백엔드 코드 구조·레이어 규칙. **코드 구조·작성 방식은 이 문서가 `04_백엔드_설정.md`보다 우선한다.**
> 1~3절은 일반 규칙이고, **4절이 이 프로젝트에 적용한 결정**이다. 둘이 다르면 4절을 따른다.

## 1. 루트 패키지

`org.example.{project}` — 이 프로젝트는 **`org.example.chaenggim`**.

## 2. 구조

```
org.example.{project}
├── domain/{domain_name}
│   ├── controller       # REST API 엔드포인트
│   ├── service          # 단일 도메인 비즈니스 로직 및 트랜잭션 단위
│   ├── facade           # 다중 서비스 오케스트레이션 / 분산 락 / 트랜잭션 경계 분리
│   ├── repository       # Spring Data JPA 및 QueryDSL Custom 구현체
│   ├── entity           # JPA Entity
│   ├── dto              # Request / Response records
│   └── event            # 이벤트 발행(Producer), 리스너(Listener), 컨슈머(Consumer)
├── infra                # 외부 연동 모듈 (PG, SMS, 외부 메시징 등)
└── global
    ├── config           # Security, Redis, Kafka, QueryDSL, Jackson, Auditing 설정
    ├── error            # ErrorCode, BusinessException, GlobalExceptionHandler
    ├── response         # ApiResponse, PageResponse
    ├── filter           # JWT 인증/인가 필터
    └── entity           # BaseTimeEntity (createdAt, updatedAt 등 공통 엔티티)
```

- 모든 인프라성 설정(JPA Auditing, QueryDSL, Redis, Redisson, Kafka 등)은 `global/config/`의 단일 Config 클래스로 관리한다. 도메인 패키지 내부에서 `@Configuration`을 중복 선언하지 않는다.
- 설정 값 클래스(`@ConfigurationProperties`) 위치
  - 한 도메인에서만 쓰는 설정은 `domain/{도메인}/config`에 둘 수 있다. 예: `domain/search/config/RecipeSearchProperties`
  - 여러 도메인이 같이 쓰는 설정은 `global/config`에 둔다. 예: `global/config/SseProperties`

## 3. 레이어별 구현 규칙

### 3.1 Controller

- 반환 타입은 항상 `ResponseEntity<ApiResponse<T>>` 형태를 유지한다. 원시값, 단순 DTO, Entity 직접 반환 금지.
- 의존성 주입은 `@RequiredArgsConstructor` + `private final`을 사용한다.
- 입력값 검증은 `@Valid`를 필수로 적용하고, 요청 파라미터는 Request record로 수신한다.

### 3.2 Service & Transaction

- 클래스 상단에 `@Transactional(readOnly = true)`를 기본 선언하고, CUD 메서드에만 `@Transactional`을 명시한다.
- 더티 체킹: 엔티티 수정 시 `repository.save()`를 명시적으로 호출하지 않고, 영속 상태 엔티티의 비즈니스 메서드를 호출한다.
- 외부 API 통신이나 카프카 메시지 발행은 DB 트랜잭션과 묶지 않으며, `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`를 활용한다.

### 3.3 Entity

- 클래스 선언: `@Entity`, `@Table(name = "...")`, `@Getter`, `@NoArgsConstructor(access = AccessLevel.PROTECTED)`.
- 기본키: `@Id`, `@GeneratedValue(strategy = GenerationType.IDENTITY)`.
- 공통 감사 필드: `BaseTimeEntity`를 상속해 createdAt, updatedAt을 관리한다.
- 연관관계: 모든 연관관계 매핑(`@ManyToOne`, `@OneToOne` 등)은 `fetch = FetchType.LAZY` 필수.
- 생성자/빌더: 엔티티 내부에 `create(...)` 등 정적 팩토리 메서드를 두지 않는다. private(또는 protected) 생성자 위에 `@Builder`를 선언해 필드를 초기화한다.
- `@Setter` 절대 금지. 상태 전이 및 필드 변경은 도메인 행위 중심의 엔티티 메서드로 캡슐화한다.

### 3.4 DTO

- 모든 DTO는 불변 객체인 Java `record`로 작성한다 (필요 시 Response 조립용 `@Builder` 허용).
- Request → Entity: 입력값·필수값 검증 및 엔티티 생성 변환 책임은 Request DTO가 가진다. Request record 내부에 `toEntity(...)`를 구현해 `Entity.builder()...build()`로 엔티티를 생성한다.
- Entity → Response: Response record 내부에 `public static Response from(Entity entity)`를 구현해 DTO가 조립 책임을 가진다.
- 유효성 검증: Request 필드에 `@NotBlank`, `@NotNull`, `@Min` 등을 선언하고 상세한 message를 작성한다.
- 날짜/시간 필드는 ISO-8601 문자열 기준 직렬화를 기본으로 하며, 필요 시 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`를 명시한다.

### 3.5 Repository & QueryDSL

- 기본 CRUD는 `JpaRepository<Entity, Long>`을 상속한다.
- 동적 쿼리, 복잡한 조인은 `{Domain}RepositoryCustom` 인터페이스와 `{Domain}RepositoryImpl` 구현체로 분리하여 `JPAQueryFactory`로 구현한다.
- N+1 문제 방지를 위해 연관 엔티티 조회 시 `join().fetchJoin()`을 적극 사용한다.
- 대량 배치 수정/삭제는 건당 쿼리 방지를 위해 Bulk 연산(`execute()` 또는 `@Modifying`)을 적용하고 영속성 컨텍스트 초기화를 처리한다.

## 4. 이 프로젝트 적용 결정 (2026-11-09 사용자 확정)

| # | 항목 | 결정 |
| --- | --- | --- |
| K1 | 루트 패키지 | `org.example.chaenggim`, Gradle group `org.example` |
| K2 | 도메인 패키지 | `domain/doctor`, `domain/visit`, `domain/question`, `domain/commitment`, `domain/home`, `domain/seed` |
| K3 | 사용하지 않는 패키지 | `facade`, `event`, `infra`, `global/filter`(로그인 없음), `PageResponse`(페이징 없음). **필요해질 때만** 만든다 |
| K4 | QueryDSL | **도입하지 않는다.** 조회는 Spring Data 메서드 이름 또는 `@Query`(JPQL). 네이티브 쿼리 금지. fetch join은 JPQL `join fetch`로 한다 |
| K5 | 응답 | 모든 컨트롤러는 `ResponseEntity<ApiResponse<T>>`. 형식은 `05_API_명세.md` 1절 |
| K6 | 예외 | `ErrorCode`(enum) + `BusinessException` 하나로 통일. 필드 에러는 `BusinessException`이 `List<FieldErrorItem>`을 함께 담는다 (`02_도메인_규칙.md` 6절) |
| K7 | 엔티티 생성 | 정적 팩토리 `create(...)` 없음. private 생성자 + `@Builder`. 질문·약속의 `doctor`는 생성자에서 `visit.getDoctor()`로 채우므로 빌더 인자로 받지 않는다 |
| K8 | Lombok | `@Getter`, `@Builder`, `@RequiredArgsConstructor`, `@NoArgsConstructor(access = PROTECTED)` 허용. `@Setter`, `@Data` 금지 |
| K9 | 날짜 JSON | Jackson 기본(ISO-8601) 그대로. `@JsonFormat`은 쓰지 않는다 (`05_API_명세.md`의 날짜 형식 유지) |
| K10 | Request → Entity | `toEntity(...)`는 엔티티로 그대로 옮길 수 있는 요청(의료진 등록)에만 둔다. 방문 작성처럼 서비스 검사(날짜·기한)와 연관 엔티티가 필요한 경우는 서비스에서 `builder()`로 만든다 |
